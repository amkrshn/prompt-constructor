# Конструктор запросов — подробная инструкция пользователя

## 1. Что это такое

**Конструктор запросов** помогает превратить обычное описание рабочей задачи в структурированный запрос для искусственного интеллекта.

Пользователю не нужно самостоятельно продумывать полную структуру запроса. Достаточно описать задачу, при необходимости добавить исходные данные и выбрать важные параметры. Конструктор запросов объединит их в готовое задание, которое можно передать в целевое ИИ-приложение.

Инструмент поддерживает три основных режима:

- **Тексты и документы**;
- **Изображения и визуализации**;
- **Презентации**.

> Конструктор запросов не заменяет ИИ-модель и не выполняет задачу самостоятельно. Его функция — подготовить понятный, полный и непротиворечивый запрос.

---

## 2. Общий принцип работы

Для большинства задач достаточно пройти шесть шагов:

1. **Выберите тип результата** — текст, изображение или презентация.
2. **Опишите задачу** — что именно нужно получить.
3. **Добавьте контекст и исходные данные**, если они важны для результата.
4. **Укажите аудиторию и формат**, если это влияет на подачу.
5. **Настройте дополнительные параметры** только при необходимости.
6. **Проверьте готовый запрос** и передайте его в целевое приложение.

Главное правило:

> Сначала сформулируйте, **что необходимо получить и зачем**, а уже затем настраивайте стиль, формат, роль и визуальное оформление.

Необязательно заполнять все поля. Если параметр несущественен, его лучше оставить для автоматического подбора.

---

# 3. Режим «Тексты и документы»

Этот режим подходит для:

- анализа информации;
- подготовки документов;
- редактирования текста;
- деловой переписки;
- составления планов;
- генерации идей;
- подготовки инструкций;
- создания кратких сводок.

## 3.1. Выбор сценария

Сначала выберите наиболее подходящий сценарий.

Основные варианты:

- **Анализ** — сравнение данных, вариантов, показателей или предложений;
- **Редактура** — улучшение существующего текста;
- **Письмо** — подготовка делового письма;
- **План** — создание плана работ, проекта или последовательности действий;
- **Идеи** — поиск нескольких вариантов решения;
- **Объяснение** — инструкция или обучающий материал;
- **Сводка** — сокращение большого объёма информации;
- **Документ** — подготовка служебной записки, отчёта, технического задания и других документов.

Выбор сценария помогает Конструктору запросов добавить в итоговый запрос подходящий способ работы.

## 3.2. Поле «Что нужно сделать?»

Это главное поле.

Опишите задачу обычным рабочим языком. Лучше сразу указать действие, объект анализа и ожидаемый результат.

### Хороший пример

```text
Сравни три предложения поставщиков упаковки по цене,
срокам поставки, условиям оплаты и рискам.
Подготовь вывод для руководителя закупок.
```

### Слишком общий вариант

```text
Сравни поставщиков.
```

Чем яснее сформулирована задача, тем меньше вероятность получить общий или нецелевой ответ.

## 3.3. Контекст и исходные данные

В этом разделе указываются сведения, которые ИИ должен учитывать.

Например:

```text
Поставщик А:
Цена — 125 руб.
Срок — 14 дней.
Оплата — 100% после поставки.

Поставщик Б:
Цена — 118 руб.
Срок — 30 дней.
Предоплата — 50%.
```

Также здесь можно указать:

- ограничения;
- текущую ситуацию;
- показатели и факты;
- особенности проекта;
- критерии оценки;
- требования заказчика;
- уже принятые решения.

Если исходные материалы находятся в файле, приложите файл в целевом ИИ-приложении после передачи запроса.

## 3.4. Ожидаемый результат

Поле помогает объяснить, **зачем выполняется задача**.

Примеры:

```text
Помочь руководителю выбрать поставщика для пилотной закупки.
```

```text
Подготовить материал для обсуждения на совещании.
```

```text
Сформировать основу для технического задания.
```

Это особенно полезно для аналитических, проектных и управленческих задач.

---

# 4. Формат ответа

Можно заранее определить форму результата.

Доступные варианты могут включать:

- текст;
- таблицу;
- список;
- план;
- письмо;
- инструкцию;
- краткую справку;
- документ.

Если подходящий формат неочевиден, оставьте **«Подобрать по задаче»**.

В этом случае ИИ сможет самостоятельно выбрать удобную структуру, например сочетать краткий текст, таблицу и выводы.

---

# 5. Стиль и подробность

## 5.1. Стиль

Стиль определяет характер подачи.

Например:

- деловой;
- официальный;
- простой, без лишних терминов;
- дружелюбный;
- убедительный;
- живой и выразительный.

Если стиль не принципиален, используйте автоматический подбор.

## 5.2. Подробность

Обычно доступны три уровня:

- **кратко** — только главное;
- **умеренно подробно** — оптимальный вариант для большинства рабочих задач;
- **подробно** — с пояснениями и примерами.

Не выбирайте максимальную подробность автоматически: для руководительской справки она может только ухудшить результат.

---

# 6. Точные настройки

Раздел используется, когда необходимо более строго управлять результатом.

## 6.1. Роль ИИ

Роль задаёт профессиональную позицию, с которой ИИ должен выполнять задачу.

Примеры:

```text
Бизнес-аналитик
```

```text
Экономист
```

```text
Руководитель проекта
```

```text
Системный аналитик
```

```text
Редактор деловых текстов
```

Выбирайте роль по содержанию задачи, а не по должности пользователя.

## 6.2. Аудитория

Укажите, кто будет читать или использовать результат.

Например:

```text
Руководитель подразделения
```

```text
Проектная команда
```

```text
Внешний партнёр
```

```text
Новые сотрудники
```

Один и тот же материал для руководителя и специалиста может требовать разной глубины и структуры.

---

# 7. Если данных не хватает

Конструктор запросов позволяет заранее определить поведение ИИ при недостатке информации.

### Уточнить только критичное

Рекомендуемый вариант по умолчанию.

ИИ задаёт вопросы только тогда, когда без ответа нельзя получить полезный и достоверный результат.

### Сделать черновик с пометками

ИИ выполняет максимально возможную часть работы, а неизвестные данные отмечает, например:

```text
[уточнить]
```

Подходит для документов, планов и проектных материалов.

### Сначала задать вопросы

ИИ сначала уточняет цель и недостающие данные, а затем переходит к выполнению задачи.

Используйте для сложных или плохо формализованных запросов.

---

# 8. Свобода решения

Этот параметр определяет, насколько активно ИИ может изменять структуру и предлагать собственные варианты.

### Строго следовать заданию

Используйте для:

- официальных документов;
- редактирования;
- задач с жёсткими требованиями;
- работы с утверждёнными формулировками.

### Улучшать структуру и подачу

Универсальный режим для большинства рабочих задач.

ИИ может улучшить логику и форму ответа, сохраняя ваши требования.

### Предлагать творческие подходы

Подходит для:

- генерации идей;
- рекламных концепций;
- визуальных задач;
- нестандартных презентаций.

---

# 9. Режим «Изображения»

Этот режим используется для подготовки задания на:

- инфографику;
- диаграмму;
- постер;
- обложку;
- иллюстрацию;
- рекламное изображение.

## 9.1. Основная задача

Опишите, что должно быть изображено и для чего.

Пример:

```text
Создай обложку презентации о цифровизации производства.
Справа должна находиться современная производственная линия,
слева — свободная область для заголовка.
```

Если вы не уверены в композиции, стиле или пропорциях, не задавайте их вручную — оставьте автоматический подбор.

## 9.2. Свобода оформления

Можно выбрать один из подходов:

- автоматический подбор свободных параметров;
- более смелые визуальные решения;
- строгое следование вашему описанию.

Даже при творческом режиме исходные факты, числа, точные надписи и обязательные требования не должны изменяться.

---

# 10. Диаграммы и инфографика

Для визуализации данных лучше передавать значения структурированно.

Например:

```text
Месяц; Продажи
Январь; 120
Февраль; 135
Март; 150
```

Можно дополнительно указать, что важно показать:

- сравнение категорий;
- изменение во времени;
- доли;
- зависимости;
- распределение;
- этапы процесса;
- сроки и последовательность работ.

Если вы не знаете подходящий вид диаграммы, выберите **«Подобрать по данным»**.

## 10.1. Когда нужен SVG

Если необходимо точно отобразить числа, подписи или связи, используйте режим точной визуализации в **SVG**.

SVG предпочтителен для:

- диаграмм;
- блок-схем;
- организационных структур;
- схем связей;
- визуализации точных числовых данных.

Обычная генерация изображения хорошо подходит для визуальной концепции, но не должна использоваться как подтверждение точности чисел.

---

# 11. Текст на изображении

Возможны несколько подходов.

### Без текста

Используйте, если все подписи будут добавляться позже в редакторе.

### Наложить текст отдельно

Наиболее надёжный вариант для презентаций и маркетинговых материалов.

ИИ создаёт изображение, а заголовок и подписи добавляются отдельно.

### Предложить текст

ИИ может предложить короткий заголовок, подпись или призыв к действию.

### Встроить точные надписи

Используйте только когда текст обязательно должен быть частью изображения.

Встроенные надписи рекомендуется проверять вручную.

---

# 12. Режим «Презентации»

Этот режим помогает подготовить полное задание на создание презентации.

Можно определить:

- тему;
- цель;
- аудиторию;
- тип презентации;
- количество слайдов;
- длительность выступления;
- язык;
- формат слайдов;
- структуру;
- палитру;
- шрифты;
- требования к визуализации;
- формат результата.

## 12.1. Тема

Опишите предмет презентации.

Пример:

```text
Результаты проекта автоматизации закупок за первое полугодие.
```

## 12.2. Цель

Укажите, что аудитория должна понять или сделать после просмотра.

Например:

```text
Согласовать переход проекта на следующий этап.
```

Это помогает сформировать презентацию как последовательную аргументацию, а не набор разрозненных слайдов.

## 12.3. Тип презентации

Можно выбрать:

- управленческую;
- отчётную или аналитическую;
- обучающую;
- проектную;
- коммерческую;
- презентацию для выступления или конференции.

Если тип сложно определить, оставьте автоматический подбор.

---

# 13. Количество слайдов и время выступления

Если презентация предназначена для выступления, желательно указать время.

Например:

```text
10 минут
```

и ориентировочное число слайдов:

```text
8 слайдов
```

ИИ должен учитывать связь между временем выступления и объёмом материала.

Если число слайдов не принципиально, оставьте поле пустым и позвольте подобрать объём по задаче.

---

# 14. Палитра и шрифты

Конструктор запросов содержит нейтральные варианты оформления.

Например:

- деловая синяя палитра;
- природная зелёная;
- графитовая с акцентом;
- минималистичная монохромная.

При необходимости можно задать собственные HEX-цвета.

Пример:

```text
Фон: #FFFFFF
Текст: #172B4D
Акцент: #315DA8
```

Для шрифтов можно использовать готовые пары или указать свои.

Важно: наличие выбранной гарнитуры зависит от среды, в которой затем создаётся презентация. Если шрифт недоступен, его нельзя считать автоматически применённым.

---

# 15. Порядок создания презентации

Для сложных презентаций рекомендуется режим:

**«Сначала план, затем слайды после согласования»**.

Он позволяет сначала проверить:

- логику истории;
- последовательность слайдов;
- основные тезисы;
- наличие обязательных разделов;
- соответствие цели презентации.

После согласования структуры можно переходить к полноценному оформлению.

Для простых задач можно использовать режим **«Сразу подготовить презентацию»**.

---

# 16. Предпросмотр готового запроса

Конструктор запросов показывает итоговый запрос в области предпросмотра.

Он обновляется автоматически при изменении параметров.

Перед передачей проверьте:

- правильно ли сформулирована задача;
- присутствуют ли необходимые исходные данные;
- верно ли указана аудитория;
- нет ли противоречащих требований;
- не добавлены ли лишние ограничения;
- не пропущены ли обязательные числа, названия и условия.

---

# 17. Передача запроса

После подготовки запрос можно:

- передать в подключённое приложение;
- скопировать;
- сохранить в `.txt`.

При интеграции Конструктор запросов передаёт сформированный текст целевому приложению. Уже оно определяет, куда отправить запрос и какую ИИ-модель использовать.

---

# 18. Когда не нужно заполнять все настройки

Одна из частых ошибок — стремление заполнить каждое поле.

Для простой задачи обычно достаточно:

```text
Сценарий
+
Что нужно сделать?
+
при необходимости исходные данные
```

Пример:

```text
Сценарий: Анализ

Задача:
Сравни два варианта организации технической поддержки.
Выдели преимущества, недостатки и основные риски.
Результат нужен для обсуждения с руководителем.
```

Этого уже достаточно для формирования качественного запроса.

---

# 19. Практические рекомендации

## Формулируйте конечный результат

Вместо:

```text
Проанализируй продажи.
```

лучше:

```text
Проанализируй продажи за квартал,
найди основные изменения и подготовь пять выводов для руководителя.
```

## Передавайте исходные данные

ИИ работает точнее, если получает конкретную информацию:

- сроки;
- стоимость;
- показатели;
- ограничения;
- критерии;
- фактические результаты.

## Не перегружайте запрос

Не задавайте десятки требований, если они не влияют на результат.

Слишком большое количество ограничений делает запрос сложнее и иногда ухудшает качество ответа.

## Используйте автоматический подбор

Если вы не знаете:

- какой формат ответа выбрать;
- какую диаграмму использовать;
- какой стиль изображения подходит;
- сколько слайдов требуется;

оставьте соответствующий параметр в режиме автоматического выбора.

---

# 20. Пример полного рабочего запроса

Допустим, необходимо сравнить предложения трёх поставщиков.

В Конструкторе запросов можно заполнить:

```text
Сценарий:
Анализ

Задача:
Сравни предложения трёх поставщиков оборудования.

Цель:
Помочь руководителю выбрать поставщика для пилотной закупки.

Аудитория:
Руководитель подразделения.

Формат:
Таблица + краткие выводы.

Исходные данные:
Поставщик А — цена 1,2 млн руб., срок 30 дней.
Поставщик Б — цена 1,35 млн руб., срок 14 дней.
Поставщик В — цена 1,1 млн руб., срок 45 дней.

Дополнительные требования:
Учитывай стоимость, срок поставки и риск задержки.
Не делай окончательный выбор, если данных недостаточно.
```

Конструктор запросов преобразует эти параметры в структурированное задание для ИИ.

---

# 21. Краткая памятка

Для большинства задач достаточно ответить на шесть вопросов:

1. **Что сделать?** — сформулируйте конкретную задачу.
2. **Для чего?** — укажите ожидаемый результат.
3. **Для кого?** — определите аудиторию.
4. **На основе чего?** — передайте необходимые исходные данные.
5. **В каком виде?** — выберите формат результата или оставьте автоматический подбор.
6. **Какие ограничения действительно важны?** — добавьте только существенные требования.

Чем яснее сформулированы эти элементы, тем точнее будет итоговый запрос и результат работы ИИ.
