# Конструктор запросов — быстрая памятка

**Конструктор запросов** помогает превратить обычное описание задачи в структурированный запрос для ИИ.

Поддерживаются три режима:

- **Тексты и документы**;
- **Изображения**;
- **Презентации**.

## Как работать

Для большинства задач достаточно шести шагов:

1. **Выберите тип результата.**
2. **Опишите, что нужно сделать.**
3. **Добавьте исходные данные**, если без них нельзя получить точный результат.
4. **Укажите цель и аудиторию**, если они влияют на подачу.
5. **Настройте формат и ограничения** только при необходимости.
6. **Проверьте готовый запрос** и передайте его в целевое приложение.

> Не нужно заполнять все поля. Если параметр несущественен, оставьте автоматический подбор.

---

## Тексты и документы

Выберите подходящий сценарий:

- Анализ;
- Редактура;
- Письмо;
- План;
- Идеи;
- Объяснение;
- Сводка;
- Документ.

### Хорошая постановка задачи

```text
Сравни три предложения поставщиков по цене,
срокам, условиям оплаты и рискам.
Подготовь краткий вывод для руководителя.
```

Старайтесь указать:

- **что сделать**;
- **для чего**;
- **для кого**;
- **на основе каких данных**;
- **в каком виде нужен результат**.

Для большинства рабочих задач подходят настройки:

```text
Формат: Подобрать по задаче
Подробность: Умеренно подробно
Свобода решения: Улучшать структуру и подачу
Если данных не хватает: Уточнить только критичное
```

---

## Изображения

Опишите:

1. что должно быть изображено;
2. где будет использоваться изображение;
3. что обязательно сохранить;
4. нужен ли текст внутри изображения.

Если стиль и композиция не принципиальны — оставьте их на автоматический подбор.

### Для точных данных

Числа лучше передавать структурированно:

```text
Месяц; Продажи
Январь; 120
Февраль; 135
Март; 150
```

Для диаграмм и схем с точными значениями предпочтителен **SVG**.

Для обложек, иллюстраций и визуальных концепций подходит обычная генерация изображения.

---

## Презентации

Минимально укажите:

- тему;
- цель;
- аудиторию;
- исходные материалы.

При необходимости добавьте:

- число слайдов;
- время выступления;
- язык;
- формат;
- палитру;
- шрифты;
- обязательную структуру.

Для сложных презентаций используйте:

**«Сначала план, затем слайды после согласования».**

Это позволяет проверить логику презентации до начала оформления.

---

## Перед передачей запроса проверьте

- задача сформулирована однозначно;
- ключевые данные указаны;
- числа и названия не потеряны;
- требования не противоречат друг другу;
- в запросе нет лишних ограничений.

---

## Главное правило

Хороший запрос отвечает на вопросы:

```text
Что сделать?
Для чего?
Для кого?
На основе чего?
В каком виде?
Какие ограничения важны?
```

Если эти шесть пунктов понятны, остальные настройки можно оставить Конструктору запросов и ИИ.
